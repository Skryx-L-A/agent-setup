# Regel-Persistenz — wie eine vereinbarte Regel dauerhaft wird

Ausgelagert am 2026-08-26 aus `~/.claude/CLAUDE.md`, weil die Datei ihre Obergrenze erreicht
hatte. Der Wortlaut ist unveraendert; nur der Ort hat sich geaendert. Ausloeser: Du willst eine
in einer Session vereinbarte Regel oder Praeferenz festschreiben.

**Rule persistence (2026-07-10):** a rule/preference der Nutzer agrees and does NOT call
session-only gets persisted immediately and unprompted — in `CLAUDE.md` (Standing rules)
and/or the matching vault note (`10-global/` or the project branch) — so every future session
honors it; confirm briefly what was persisted and where.

**So knapp wie moeglich formulieren (2026-07-28):** Regel, Datum, der eine Satz Begruendung —
kein nacherzaehlter Vorfall. `CLAUDE.md` wird jede Session geladen; jede ueberfluessige Zeile
kostet dauerhaft Tokens. Ausfuehrliches gehoert in eine `type: incident`-Vault-Note, in
`CLAUDE.md` steht der Wikilink.

**Wohin genau (2026-08-03):** eine neue Regel gehoert nur dann in eine immer geladene Datei,
wenn sie OHNE Ausloeser gilt. Alles, was erst bei einer bestimmten Taetigkeit greift, kommt
nach `~/.claude/regeln/<thema>.md` und wird im Verweisbaum von `CLAUDE.md` mit seinem
Ausloeser eingetragen — eine Zeile dort, der Wortlaut hier.

**Kuerzen heisst auslagern, nie streichen.** Die stehende Anweisung „nie bestehende
Anweisungen loeschen" (2026-07-17) gilt auch dann, wenn eine Datei ihre Obergrenze reisst.
Diese Datei ist der Beleg dafuer, wie das aussieht.
