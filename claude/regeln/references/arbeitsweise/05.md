## Code hygiene

- **Wer committet, nennt seine Pfade — `git add -A` nie (2026-08-11, forensisch belegt):** gilt
  für Agenten wie für automatische Committer, im Vault und in jedem Repo, in dem parallel
  gearbeitet wird. Ein `git add -A` im Gärtner sammelte 31 Tage lang Fremdes ein: zehn Commits
  trugen Dateien, die der Lauf nie geschrieben hat, darunter 109 Zeilen halbfertiger Quelltext
  einer anderen Sitzung um 3:18 nachts unter der Nachricht „gardener: pre-run snapshot". Derselbe
  Griff aus einer Agenten-Sitzung von Hand (`9b7829f`) hat es unabhängig davon wiederholt — die
  Reparatur im Werkzeug erreicht diesen zweiten Weg nicht, nur diese Regel tut das.
  **Ein abgelehnter Befehl hat auch das nicht getan, was VOR ihm in der Kette stand
  (2026-09-01):** der Riegel greift, bevor die Shell startet, also lief bei
  `echo … >> LOG.md && git add -A && git commit` weder das `echo` noch sonst etwas. Wer nach
  einer Ablehnung nur den verbotenen Teil ersetzt und neu absendet, verliert die Zeilen davor
  still — sie sahen aus, als wären sie geschrieben. Nach jeder Ablehnung prüfen, was von der
  Kette tatsächlich passiert ist, statt es anzunehmen. **Der Riegel trifft dabei auch Text, der
  über den Befehl nur spricht:** dieser Absatz selbst ließ sich nur schreiben, indem die
  verbotene Zeichenkette im Skript aus Teilen zusammengesetzt wurde. Wer eine Regel
  dokumentiert, die einen gesperrten Befehl zitiert, braucht diesen Umweg.
- **Vor jedem Push nach main die GANZE Testsuite (2026-08-19).** Der Wortlaut steht in
  `regeln/tests-und-eingriffe.md`, Abschnitt „Die eigene Testsuite laufen lassen" (dorthin am
  2026-08-29 aus `CLAUDE.md` ausgelagert). Auf peer lag dieselbe Regel bis zum 2026-09-05
  stattdessen hier; beide Maschinen führen sie jetzt an dem einen Ort.
- Re-read the full relevant code before any commit.
- Every function gets/keeps a test; the whole suite stays green; never break existing features.
- When a change touches connected code, review and tidy/shrink it (verified green).
- Build modular and efficient — easy to extend later.
