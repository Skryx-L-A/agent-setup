## Handwerk, das dreimal in einer Nacht schiefging

- **Langläufe einzeln starten, nie verketten.** `until <fertig>; do sleep; done && <nächstes>`
  wurde dreimal abgebrochen und verlor jedes Mal den Anschluss.
- **Nie in eine Pipe schreiben, deren Rückgabewert zählt.** `| tail` liefert den Wert von
  `tail`. Ausgabe in eine Datei, Rückgabewert getrennt festhalten.
- **Commit-Nachrichten über eine Datei** (`git commit -F`), nie über die Kommandozeile: Wörter
  in Backticks werden von der Shell ausgeführt und verschwinden aus dem Text.
  **Und das gilt für JEDEN Text mit Backticks, nicht nur für Commit-Nachrichten** — am
  03.09.2026 hat es einen Kanon-Absatz an drei Stellen ausgehöhlt, genau dort, wo die
  technische Aussage stand („`"# ExecStart"` ist nicht `"ExecStart"`" wurde zu „und  ist
  nicht ."). **Ein quotierter Heredoc-Begrenzer schützt nicht, wenn das Ganze in
  `bash -c '…'` steckt**: dort greift die Ersetzung eine Ebene früher. Der Weg, der immer
  hält: den Text in eine Datei schreiben und den PFAD übergeben — `python3 skript.py`,
  `git commit -F datei`. Nie durch zwei Shell-Ebenen schicken.
- **Ausgabedateien tragen die Betriebsart im Namen.** Zwei Läufe mit verschiedener Einstellung,
  die in dieselbe Datei schreiben, erzeugen einen Vergleich zweier Welten.
